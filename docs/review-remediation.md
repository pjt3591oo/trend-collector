## 데이터와 복구

기존 초안 JSON 본문과 발행 이력을 보존한다. 검색용 근거 인덱스는 시작 시 기존 초안에서 보완하며,
새 초안과 근거 인덱스는 하나의 트랜잭션으로 저장한다. 재시도 이력과 수동 확인 이력은 별도 테이블에 남긴다.
기존 pending 기록을 임의로 failed/published로 바꾸지 않는다.

수동 확인은 Threads 계정을 실제로 확인한 운영자의 명시적 입력이다. 서비스가 제공자 상태를 자동 증명하지 않는다.
웹의 확인 API는 기존 CSRF·Origin·확인 검사를 사용하고, 계정 조회·게시 요청을 전송하지 않는다.
계정마다 별도 journal을 사용해야 한다. 현행 UI는 Threads를 대상으로 하며 다계정 통합은 이번 범위에 포함하지 않았다.

분석 목록은 DB 기준이다. DB에 없는 과거 파일만의 보고서는 자동으로 가져오지 않는다.
기존 report.json/Markdown 파일을 삭제하지 않는다. 파일 내보내기 실패 시 분석 DB는 계속 조회할 수 있다.

## 검증

- 로컬 단위·통합 테스트 98개 통과. 이전 경로 전용 테스트 2개 제거, 회귀 테스트 13개 추가.
- DB 실패 시 파일 미생성, 파일 내보내기 실패 시 분석 보존, 기존 초안 인덱스 보완 및 원문 보존 확인.
- 한 페이지 조회에서 요청한 초안만 복원하고 발행 이력 연결은 한 번 사용하는지 확인.
- 확정 실패 재시도, 불명 결과 중복 차단, 수동 확인 검증·CSRF, 동시 발행 선점 확인.
- 실제 수집·LLM 요청·Threads 게시·실제 사용자 DB 마이그레이션은 실행하지 않았다.
- Graphify 구조 재추출과 import AST 대조: 73개 코드 파일, 634개 노드·2,053개 관계. 명시적 import 순환 없음, 4문장 이상 동일 AST 함수 본문 없음.
  의미상 중복 전체나 동적 DI 호출의 정확성을 증명하는 결과는 아니다.
- 산출물: graphify-out/full-review/graph.html, graph.json, summary.json.

페이지 처리는 DB에서 수행하지만 상태 집계와 전체 개수 계산은 데이터 규모에 따라 비용이 증가한다.
전문 검색 인덱스나 다계정 이력 분리는 별도 확장 영역이다.
